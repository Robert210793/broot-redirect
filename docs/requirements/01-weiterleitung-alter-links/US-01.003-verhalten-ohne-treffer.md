# US-01.003: Verhalten bei fehlendem Treffer

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** festlegen, was mit alten Links geschieht, auf die keine Regel zutrifft
**damit** Benutzer auch ohne passende Regel nicht ins Leere laufen

## Akzeptanzkriterien

- [x] Bei «Verhalten ohne Treffer» = «Standard-Weiterleitung» leitet das System mit HTTP 302 auf die Standard-Zieldomain weiter
- [x] Ist die Standard-Zieldomain leer, wird statt der Weiterleitung die Info-Seite angezeigt
- [x] Bei «Verhalten ohne Treffer» = «404 / Info-Seite» oder einem unbekannten Wert wird die Info-Seite angezeigt
- [x] Die Auflösung durch die Info-Seite antwortet ohne Treffer mit 404, sofern keine Smart Search greift
- [ ] Die Info-Seite zeigt ohne Treffer den Zustand «Seite nicht gefunden» (siehe US-02.001)

## Hinweise

- Die Werte von «Verhalten ohne Treffer» sind `RedirectToDefault` (Standard), `SmartSearch` und `Return404`; die Smart Search ist in US-01.004 beschrieben.
- Belegende Tests: `RedirectMiddlewareTests`, `RedirectControllerTests`.

## Offene Fragen

- [ ] **F1 · Option «404 zurückgeben» liefert keinen HTTP-Status 404:** Das Admin-Panel bietet «404 zurückgeben» an. Tatsächlich wird die Info-Seite mit dem Zustand «Seite nicht gefunden» und HTTP-Status 200 ausgeliefert.
  - Option A: Die Option in «Info-Seite anzeigen» umbenennen — ✅ Beschriftung entspricht dem Verhalten / ❌ keine
  - Option B: Die Info-Seite in diesem Fall mit HTTP-Status 404 ausliefern — ✅ Beschriftung stimmt, Suchmaschinen und Monitoring erkennen tote Links / ❌ Änderung am SPA-Fallback nötig
  - **Empfehlung:** Option A, weil Benutzer in jedem Fall die Info-Seite sehen und der Status für den Anwendungsfall (Links aus E-Mails und Dokumenten) keine Rolle spielt.
