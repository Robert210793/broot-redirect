# US-01.004: Smart Search bei fehlendem Treffer

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Benutzer mit einem alten Link, für den keine Regel existiert
**möchte ich** auf eine Suche in der neuen Ablage geleitet werden, die bereits nach dem Dokument sucht
**damit** ich das Dokument trotzdem schnell finde

## Akzeptanzkriterien

- [x] Bei «Verhalten ohne Treffer» = «Smart Search» leitet das System mit HTTP 302 auf eine Such-URL weiter, die aus der konfigurierten Such-Basis-URL und dem Suchbegriff besteht
- [x] Ist ein Regex konfiguriert, wird der Suchbegriff aus dessen erster Capture-Group gelesen und URL-dekodiert
- [x] Fehlt der Regex, ist er ungültig, trifft er nicht oder liefert eine leere Gruppe, wird der Suchbegriff aus dem letzten Pfadsegment abgeleitet
- [x] Beim letzten Pfadsegment wird die Dateiendung entfernt, `-` und `_` werden zu Leerzeichen, mehrfache Leerzeichen werden zusammengefasst und die Query ignoriert (z. B. `/docs/annual-report-2023.pdf` → «annual report 2023»)
- [x] Der Suchbegriff wird URL-kodiert, ausser die Einstellung «Kodierung überspringen» ist aktiv
- [x] Ist keine Such-Basis-URL konfiguriert oder lässt sich kein Suchbegriff ableiten (z. B. Wurzelpfad), wird die Info-Seite angezeigt
- [x] Die Auflösung durch die Info-Seite liefert die Such-URL als Smart-Search-Fallback mit Qualität 0 und Stufe Rot
- [ ] Die Info-Seite beschriftet die Such-URL mit «Suche (Smart Search)» und zeigt die Erklärung für «kein Treffer»

## Hinweise

- Regex-Timeout für die Suchbegriff-Extraktion: 2 Sekunden.
- Belegende Tests: `SmartSearchServiceTests`, `RedirectMiddlewareTests`, `RedirectControllerTests`.
