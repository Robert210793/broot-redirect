# US-01.005: System- und Admin-Pfade von der Weiterleitung ausnehmen

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich**, dass die Seiten des Admin-Panels und die API nie als alte URLs behandelt werden
**damit** das Admin-Panel unter derselben Adresse wie die Weiterleitung erreichbar bleibt

## Akzeptanzkriterien

- [x] Pfade unter `/api/` werden nicht weitergeleitet
- [x] Der Wurzelpfad `/` wird nicht weitergeleitet
- [x] `/login` wird nicht weitergeleitet
- [ ] Die Admin-Routen `/rules`, `/global-rules`, `/settings`, `/import`, `/stats`, `/blocked-ips` und `/validate` sowie deren Unterpfade werden nicht weitergeleitet (Gross-/Kleinschreibung wird ignoriert)
- [ ] Auf dem Wurzelpfad zeigt die Info-Seite die Standard-Zieldomain als neue URL mit Qualität 100 (grün), ohne einen Tracking-Eintrag zu schreiben

## Hinweise

- Eine neue Admin-Route muss sowohl in den Angular-Routen als auch in der Liste der ausgenommenen Pfade der Weiterleitung eingetragen werden — sonst wird die neue Admin-Seite selbst als alte URL behandelt.
- Belegende Tests: `RedirectMiddlewareTests`.
