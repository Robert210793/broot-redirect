# US-03.002: Wildcard-Regeln (exakter Pfad) anwenden

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** eine Regel für genau eine alte URL anlegen, optional eingeschränkt auf bestimmte Query-Parameter
**damit** einzelne Dokumente zuverlässig auf ihr neues Gegenstück zeigen, auch wenn sich mehrere alte URLs nur in der Query unterscheiden

## Akzeptanzkriterien

- [x] Eine Regel vom Typ «Wildcard» greift, wenn der normalisierte Pfad der Anfrage exakt dem Pfad des Matchers entspricht; die Qualität beträgt dann 100
- [x] Enthält der Matcher eine Query, greift die Regel nur, wenn die Anfrage alle Key/Value-Paare des Matchers enthält
- [x] Enthält die Anfrage zusätzliche Query-Parameter, greift die Regel trotzdem, mit Qualität 75
- [x] Teilen sich mehrere Regeln denselben Pfad und unterscheiden sich nur in der Query, wird die Regel gewählt, deren Query passt; mehr getroffene Query-Paare ergeben einen höheren Score
- [x] Regeln vom Typ «Wildcard» werden vor allen anderen Typen geprüft und gewinnen gegenüber teilweisen Regeln
- [ ] Bei Gleichstand gewinnt in dieser Reihenfolge: mehr getroffene Query-Paare, längerer Matcher, älteres Erstelldatum, kleinere Regel-ID

## Hinweise

- Im Admin-Panel heisst der Typ «Wildcard (exakter Pfad)», in den Validierungsmeldungen des Imports «Vollständig». Der Name «Wildcard» täuscht: Der Pfad wird exakt nachgeschlagen; ein abschliessendes `*` im Matcher bewirkt keine Präfix-Suche.
- Der Nachschlag erfolgt über einen Index auf dem reinen Pfad (ohne Query) und ist unabhängig von der Anzahl Regeln gleich schnell.
- Score: 1000 + getroffene Query-Paare × Gewicht Query-Paar + Bonus, wenn die Anzahl Query-Parameter exakt übereinstimmt.
- Belegende Tests: `RuleMatchingServiceTests`, `RuleCacheServiceTests`.
