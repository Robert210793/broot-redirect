# US-03.003: Domain-Regeln auf den Hostnamen anwenden

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** eine Regel anlegen, die nur den Hostnamen austauscht
**damit** alle URLs einer alten Domain mit unverändertem Pfad auf die neue Domain zeigen

## Akzeptanzkriterien

- [x] Eine Domain-Regel greift, wenn der Hostname der angefragten URL dem Matcher entspricht (Gross-/Kleinschreibung wird ignoriert)
- [x] Enthält der Matcher eine Query, greift die Regel nur, wenn die Anfrage alle Key/Value-Paare enthält
- [x] Die Qualität beträgt 100, bei zusätzlichen Query-Parametern in der Anfrage 75
- [x] Bei abweichendem Hostnamen oder fehlenden Query-Paaren greift die Regel nicht

## Hinweise

- Im Admin-Panel heisst der Typ «Domain», in den Validierungsmeldungen des Imports «Domain-Ersatz».
- Score: 1000 + getroffene Query-Paare × Gewicht Query-Paar.
- Die Tests prüfen das Verhalten mit vollständigen URLs inklusive Host, wie sie im Validierungswerkzeug eingegeben werden.
- Belegende Tests: `RuleMatchingServiceTests`.

## Offene Fragen

- [ ] **F1 · Domain-Regeln im Live-Betrieb wirkungslos:** Beim Aufruf einer alten URL und bei der Auflösung durch die Info-Seite wird nur Pfad und Query an das Matching übergeben, nicht der Host. Domain-Regeln vergleichen deshalb gegen einen internen Platzhalter-Host und greifen bei echten Aufrufen nie. Umgekehrt würde eine Domain-Regel mit genau diesem Platzhalter-Host auf jeden Aufruf zutreffen. Dasselbe gilt für Regeln vom Typ «Teilweise», deren Matcher nicht mit `/` beginnt. Nur im Validierungswerkzeug mit vollständigen URLs greifen sie.
  - Option A: Weiterleitung und Info-Seite übergeben die vollständige URL inklusive Host an das Matching — ✅ Domain-Regeln wirken wie dokumentiert / ❌ Regex-Regeln sehen danach ebenfalls den Host, bestehende Regex-Muster sind zu prüfen
  - Option B: Typ «Domain» entfernen bzw. bei der Erfassung sperren — ✅ keine wirkungslosen Regeln / ❌ der Anwendungsfall Domain-Wechsel entfällt
  - **Empfehlung:** Option A, weil Regelverwaltung und Validierungswerkzeug den Domain-Wechsel bereits anbieten und die Benutzer von dessen Wirkung ausgehen.
