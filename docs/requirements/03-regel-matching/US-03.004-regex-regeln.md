# US-03.004: Regex-Regeln für Sonderfälle anwenden

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** alte URLs mit einem regulären Ausdruck erkennen
**damit** ich Muster abdecken kann, die sich mit Pfad- oder Domain-Regeln nicht ausdrücken lassen

## Akzeptanzkriterien

- [x] Eine Regex-Regel greift, wenn ihr Muster auf die angefragte URL passt; Score 500, Qualität 100
- [ ] Regex-Regeln werden erst geprüft, wenn keine Regel vom Typ «Wildcard», «Teilweise» oder «Domain» greift; der erste Treffer gewinnt
- [x] Überschreitet ein Muster das konfigurierte Zeitlimit, wird es übersprungen und das nächste geprüft
- [x] Ungültige Muster werden beim Aufbau des Caches protokolliert und übersprungen, ohne den Start zu verhindern
- [x] Das Zeitlimit pro Muster ist konfigurierbar
- [ ] Ohne Konfiguration beträgt das Zeitlimit 1 Sekunde

## Hinweise

- Im Live-Betrieb wird das Muster gegen Pfad und Query geprüft (ohne Schema und Host), im Validierungswerkzeug gegen den eingegebenen Wert.
- Regex-Regeln nehmen nicht an der Überlappungsprüfung teil (siehe US-05.004).
- Belegende Tests: `RuleMatchingServiceTests`, `RuleCacheServiceTests`.

## Offene Fragen

- [ ] **F1 · Ziel-URL von Regex-Regeln wird nicht verwendet:** Der Regel-Editor verspricht «Verwende Capture Groups ($1, $2) in der Ziel-URL», die Transformation ignoriert die Ziel-URL einer Regex-Regel aber vollständig. Sie ersetzt nur Schema und Host der angefragten URL durch die Standard-Zieldomain. Im Live-Betrieb, wo nur Pfad und Query vorliegen, entsteht dabei eine ungültige URL der Form `https:///pfad`.
  - Option A: Die Ziel-URL der Regel verwenden, mit Ersetzung von Capture-Groups (`$1`, `$2`, …) — ✅ Regex-Regeln werden fachlich nutzbar / ❌ neue Transformationslogik mit Tests nötig
  - Option B: Die Ziel-URL unverändert als Ziel verwenden, ohne Capture-Groups — ✅ kleine Änderung / ❌ Muster können keine Teile der alten URL übernehmen
  - Option C: Typ «Regex» entfernen bzw. bei der Erfassung sperren — ✅ keine fehlerhaften Weiterleitungen / ❌ Sonderfälle müssen mit anderen Typen abgebildet werden
  - **Empfehlung:** Option A, weil die Ziel-URL im Admin-Panel bereits erfasst wird und Capture-Groups der übliche Nutzen von Regex-Regeln sind.
