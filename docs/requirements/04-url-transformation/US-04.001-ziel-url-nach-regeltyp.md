# US-04.001: Ziel-URL nach Regeltyp aufbauen

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich**, dass aus einer getroffenen Regel und der alten URL automatisch die passende neue URL entsteht
**damit** eine Regel viele alte URLs korrekt abbilden kann, ohne dass jede Ziel-URL einzeln gepflegt werden muss

## Akzeptanzkriterien

- [x] «Teilweise» mit Pfad-Matcher: Der Matcher wird im dekodierten alten Pfad ohne Beachtung der Gross-/Kleinschreibung gesucht und durch die Ziel-URL ersetzt; Teile davor und danach bleiben erhalten
- [x] «Teilweise» mit Pfad-Matcher, der im alten Pfad nicht vorkommt: Das Ergebnis ist Standard-Zieldomain + Ziel-URL
- [x] «Teilweise» mit Domain-Matcher: Das Ergebnis ist Ziel-URL (bzw. bei relativer Ziel-URL die Standard-Zieldomain) + alter Pfad
- [x] «Wildcard»: Der Rest des alten Pfads nach dem Matcher wird an die Ziel-URL angehängt; Query-Anteile werden mit einer Query der Ziel-URL zusammengeführt, ein Fragment der Ziel-URL steht am Ende
- [x] «Wildcard» mit relativer Ziel-URL: Die Standard-Zieldomain wird vorangestellt
- [x] «Domain»: Schema und Host der alten URL werden durch die Ziel-Domain ersetzt, Pfad und Query bleiben erhalten; `http://` wird zu `https://`
- [x] «Domain» ohne Ziel-URL: Die Standard-Zieldomain wird verwendet
- [x] Ein Fragment der alten URL bleibt erhalten
- [x] Fehlt die Standard-Zieldomain, wird ein fest eingebauter Platzhalter verwendet

## Hinweise

- Die Transformation läuft in fester Reihenfolge: 1. Basis nach Regeltyp (diese Story), 2. Suchen/Ersetzen der Regel (US-04.002), 3. globale Regeln (US-06.002), 4. Query-Strategie (US-04.003), 5. statische Query-Parameter (US-04.004).
- Prozentkodierungen der alten URL bleiben beim Typ «Wildcard» erhalten, obwohl der Abgleich auf dekodiertem Text erfolgt.
- Zum Verhalten bei Regex-Regeln siehe Offene Frage F1 in US-03.004.
- Belegende Tests: `UrlTransformServiceTests`.
- Ergänzt durch US-13.003, Korrekturen K1 und K2 (2026-10-29): «Teilweise» mit Pfad-Matcher und absoluter `http(s)`-Ziel-URL ergibt genau die Ziel-URL, ohne den Rest des alten Pfads; bei «Wildcard» mit Query im Matcher ist die Reihenfolge der Parameter der alten URL unerheblich, zusammengeführt werden nur die zusätzlichen Parameter.
