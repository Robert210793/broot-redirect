# US-04.003: Query-Parameter der alten URL weitergeben, verwerfen oder filtern

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** pro Regel steuern, welche Query-Parameter der alten URL in die neue URL übernommen werden
**damit** relevante Parameter erhalten bleiben und veraltete Parameter das Ziel nicht verfälschen

## Akzeptanzkriterien

- [x] «Query weitergeben»: Die ursprüngliche Query wird vollständig angehängt und erscheint nicht doppelt; ohne ursprüngliche Query bleibt die URL unverändert
- [x] «Query verwerfen» ohne Positivliste: Die Query wird vollständig entfernt, ein Fragment bleibt erhalten
- [x] «Query verwerfen» mit Positivliste: Nur Parameter, deren Key (und optional Wert) auf ein Muster der Liste passt, werden übernommen
- [x] Ein Eintrag der Positivliste kann den Parameter unter einem neuen Key übernehmen und die Kodierung des Werts überspringen
- [x] Einträge mit leerem oder ungültigem Muster werden übersprungen
- [x] Ist keiner der beiden Schalter aktiv, bleibt die Query so, wie sie der Basisschritt erzeugt hat
- [ ] «Query weitergeben» hat Vorrang vor «Query verwerfen»
- [ ] Jeder Parameter der alten URL wird höchstens einmal übernommen

## Hinweise

- Belegende Tests: `UrlTransformServiceTests`.
