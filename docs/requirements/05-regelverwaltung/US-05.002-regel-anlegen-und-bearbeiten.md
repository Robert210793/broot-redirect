# US-05.002: Regel anlegen und bearbeiten

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** Weiterleitungsregeln in einem Editor anlegen und ändern
**damit** ich alte URLs ohne technische Hilfe auf ihre neuen Ziele abbilden kann

## Akzeptanzkriterien

- [ ] Der Editor erfasst Matcher, Weiterleitungstyp, Ziel-URL, Info-Text und Auto-Weiterleitung sowie die Listen für beibehaltene Query-Parameter, statische Query-Parameter und Suchen/Ersetzen
- [x] Eine neue Regel wird mit Herkunft «Manuell» und dem aktuellen Erstelldatum gespeichert
- [x] Ein ungültiger Weiterleitungstyp wird mit 400 abgewiesen
- [x] Der Matcher wird vor dem Speichern normalisiert (getrimmt, abschliessender `/` entfernt, ausser der Matcher endet auf `*`)
- [x] Beim Bearbeiten behalten nicht übermittelte Felder ihren bisherigen Wert; Herkunft und Erstelldatum bleiben erhalten
- [x] Der Typ ändert sich beim Bearbeiten nur, wenn er ausdrücklich mitgeschickt wird
- [x] Eine unbekannte Regel ergibt beim Bearbeiten 404
- [ ] Eine gespeicherte Regel wirkt sofort, ohne Neustart
- [ ] Fehler der API werden im Editor beim betroffenen Feld angezeigt

## Hinweise

- Schreibvorgänge gehen zuerst in den Storage und danach in den Cache; schlägt der Storage fehl, bleibt der Cache unverändert.
- Belegende Tests: `RulesControllerTests`, `RuleCacheServiceTests`, `EntityMappingTests`.
