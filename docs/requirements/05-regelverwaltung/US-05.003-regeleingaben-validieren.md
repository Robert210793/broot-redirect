# US-05.003: Regeleingaben validieren

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** bei fehlerhaften Regeleingaben eine verständliche deutsche Fehlermeldung erhalten
**damit** keine Regeln gespeichert werden, die nicht oder falsch weiterleiten

## Akzeptanzkriterien

- [x] Der Matcher darf nicht leer und nicht zu lang sein
- [x] Ein Pfad-Matcher beginnt mit `/`; ohne `/` wird er als Domain interpretiert und darf dann keinen Pfad enthalten
- [x] Ein Regex-Matcher muss ein gültiger regulärer Ausdruck sein
- [x] Typ «Wildcard»: Die Ziel-URL ist eine vollständige URL mit `http://` oder `https://`
- [x] Typ «Teilweise»: Die Ziel-URL beginnt mit `/` oder ist eine vollständige URL
- [x] Typ «Domain»: Die Ziel-URL ist eine vollständige URL ohne Unterordner
- [x] Ziel-URL und Info-Text dürfen nicht zu lang sein
- [x] Beibehaltene Query-Parameter brauchen ein Schlüssel-Muster, statische Query-Parameter einen Key, Suchen/Ersetzen einen Suchbegriff
- [x] Mehrere Fehler werden gesammelt und gemeinsam gemeldet
- [x] Ein Matcher, der bereits existiert, wird mit 400 abgewiesen
- [ ] Der Regel-Editor prüft dieselben Regeln vor dem Absenden und zeigt die Meldung beim betroffenen Feld; die Meldung verschwindet, sobald das Feld geändert wird

## Hinweise

- Die serverseitige Validierung mit den deutschen Meldungen läuft beim Import für jeden Eintrag (siehe US-07.002).
- Belegende Tests: `RuleValidationServiceTests`, `RulesControllerTests`.

## Offene Fragen

- [ ] **F1 · Keine serverseitige Validierung beim manuellen Anlegen und Bearbeiten:** Die API prüft beim Anlegen und Bearbeiten nur Pflichtfeld, Maximallänge, Typ, Duplikat und Überlappung. Die fachlichen Regeln (z. B. Ziel-URL je Typ, gültiges Regex) prüft nur der Regel-Editor im Browser; über die API lassen sich solche Regeln trotzdem speichern.
  - Option A: Die API wendet beim Anlegen und Bearbeiten dieselbe Validierung wie beim Import an — ✅ eine verbindliche Prüfung für alle Wege / ❌ bestehende, bisher akzeptierte Eingaben können abgewiesen werden
  - Option B: Validierung im Browser belassen — ✅ keine Änderung / ❌ API-Aufrufe ausserhalb des Editors umgehen die Prüfung
  - **Empfehlung:** Option A, weil die Validierung serverseitig bereits existiert und nur nicht aufgerufen wird.
