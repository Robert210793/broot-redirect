# US-07.003: Wiederholter Import aktualisiert statt dupliziert

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** einen Export bearbeiten und erneut importieren können
**damit** ich das Regelwerk in einer Tabellenkalkulation pflegen kann, ohne Duplikate zu erzeugen

## Akzeptanzkriterien

- [x] Einträge werden bestehenden Regeln zuerst über die ID, dann über den Matcher zugeordnet; eine ungültige ID fällt auf den Matcher zurück
- [x] Der Matcher-Abgleich erfolgt über eine kanonische Form (prozentkodiert, getrimmt, ohne überflüssigen Schluss-Slash, ohne Beachtung der Gross-/Kleinschreibung), sodass unterschiedliche Schreibweisen derselben URL zusammenfinden
- [x] Deckt sich ein Eintrag inhaltlich vollständig mit der bestehenden Regel, wird er als «Unverändert» gezählt und nicht geschrieben
- [x] Bei einer Aktualisierung bleiben ID, Erstelldatum und Herkunft der bestehenden Regel erhalten; eine manuell erstellte Regel bleibt «Manuell»
- [ ] Kommt derselbe Matcher mehrfach in einer Datei vor, aktualisiert ab dem zweiten Vorkommen jedes Vorkommen die bereits angelegte Regel, statt ein Duplikat zu erzeugen
- [ ] Verglichen werden Matcher, Ziel-URL, Typ, Info-Text, die drei Query-Schalter sowie die Listen der Query-Parameter und Ersetzungen

## Hinweise

- Belegende Tests: `RuleImportExportServiceTests`, `RulesControllerTests`.
