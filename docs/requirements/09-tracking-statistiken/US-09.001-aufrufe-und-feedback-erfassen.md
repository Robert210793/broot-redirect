# US-09.001: Aufrufe und Feedback erfassen

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich**, dass jeder Aufruf eines alten Links mit Ergebnis und allfälligem Feedback erfasst wird
**damit** ich erkenne, welche alten Links noch genutzt werden und welche Regeln nicht funktionieren

## Akzeptanzkriterien

- [ ] Nach erfolgreicher Auflösung erfasst die Info-Seite den Aufruf mit alter und neuer URL, Pfad, User Agent, Referrer, Regel, Match-Qualität und Strategie («rule», «smart-search» oder «domain-fallback»); lange Werte werden gekürzt
- [x] Die API speichert einen erfassten Aufruf und liefert dessen ID für ein späteres Feedback zurück
- [x] Feedback wird nur mit dem Wert `OK` oder `NOK` angenommen, sonst 400
- [x] Eine ungültige Tracking-ID ergibt 400, ein unbekannter Eintrag 404
- [x] Eine vom Benutzer vorgeschlagene URL wird mit dem Feedback gespeichert
- [ ] Erfassen und Feedback sind ohne Anmeldung erreichbar; ein Fehler beim Erfassen blockiert die Info-Seite nicht

## Hinweise

- Automatische Weiterleitungen werden serverseitig erfasst (siehe US-01.001).
- Einträge werden nach Datum partitioniert gespeichert und nicht gecacht.
- Belegende Tests: `TrackingControllerTests`, `TableStorageTrackingRepositoryTests`, `EntityMappingTests`.

## Offene Fragen

- [ ] **F1 · Schalter «Referrer-Tracking» ohne Wirkung:** Die Einstellung `EnableReferrerTracking` wird im Admin-Panel angeboten («Einige Installationen müssen dies aus Datenschutzgründen deaktivieren») und gespeichert, der Referrer wird aber immer erfasst — von der Info-Seite und bei automatischen Weiterleitungen.
  - Option A: Bei deaktiviertem Schalter verwirft der Server den Referrer vor dem Speichern — ✅ Einstellung wirkt wie beschrieben, auch für automatische Weiterleitungen / ❌ kleine Backend-Änderung nötig
  - Option B: Schalter entfernen — ✅ kein irreführender Schalter / ❌ Datenschutzanforderungen einzelner Installationen lassen sich nicht erfüllen
  - **Empfehlung:** Option A, weil der Schalter eine Datenschutzzusage macht, die heute nicht eingehalten wird.
