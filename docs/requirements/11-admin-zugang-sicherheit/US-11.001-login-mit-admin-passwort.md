# US-11.001: Mit dem Admin-Passwort anmelden

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Administrator
**möchte ich** mich mit einem gemeinsamen Admin-Passwort anmelden
**damit** nur berechtigte Personen Regeln und Einstellungen ändern können

## Akzeptanzkriterien

- [x] Mit dem richtigen Passwort wird eine Admin-Session gestartet und die Anmeldung bestätigt
- [x] Ein falsches Passwort ergibt 401 und wird als Fehlversuch der IP gezählt
- [x] Ist die IP gesperrt, wird die Anmeldung mit 429 abgewiesen
- [ ] Das Passwort wird über SHA-256-Hashes mit laufzeitkonstantem Vergleich geprüft
- [ ] Das Session-Cookie ist `HttpOnly`, `SameSite=Lax`, in Produktion `Secure` und läuft nach 7 Tagen Inaktivität ab (konfigurierbar)
- [ ] Die Seite «Administrator-Anmeldung» fragt das Passwort ab und öffnet nach erfolgreicher Anmeldung die Regelverwaltung
- [ ] Solange das Standardpasswort aktiv ist, protokolliert die Anwendung beim Start eine Warnung

## Hinweise

- Es gibt keine Benutzerkonten, nur ein gemeinsames Passwort aus der Startkonfiguration. Ohne Konfiguration gilt das Standardpasswort `Password1` — für jede Installation zwingend zu ändern (idealerweise aus dem Key Vault).
- Verglichen wird der Hash eines Klartextwerts aus der Konfiguration; das ist keine sichere Passwortspeicherung im Sinne von Salt und KDF.
- Belegende Tests: `AuthControllerTests`.
