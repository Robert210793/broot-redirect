# US-11.003: IP nach wiederholten Fehlversuchen sperren

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Betreiber
**möchte ich**, dass eine IP nach wiederholten falschen Passworteingaben gesperrt wird
**damit** das gemeinsame Admin-Passwort nicht durch Ausprobieren erraten werden kann

## Akzeptanzkriterien

- [x] Erreicht eine IP die konfigurierte Anzahl Fehlversuche, wird sie gesperrt; darunter bleibt sie zugelassen
- [x] Eine Sperre läuft nach der konfigurierten Dauer ab
- [ ] Eine erfolgreiche Anmeldung setzt die Fehlversuche der IP zurück
- [x] Abgelaufene Sperren und Fehlversuche werden regelmässig aufgeräumt
- [ ] Ohne Konfiguration gelten 5 Fehlversuche und 24 Stunden Sperrdauer

## Hinweise

- Sperren und Fehlversuche liegen nur im Arbeitsspeicher und gehen bei einem Neustart verloren.
- Zur Ermittlung der Client-IP hinter dem Azure-Ingress siehe US-11.006, F1 — betrifft auch die Sperre: Wird für alle Clients dieselbe IP erkannt, sperren fünf Fehlversuche eines Angreifers alle Administratoren für 24 Stunden aus.
- Belegende Tests: `BruteForceProtectionServiceTests`, `AuthControllerTests`.
