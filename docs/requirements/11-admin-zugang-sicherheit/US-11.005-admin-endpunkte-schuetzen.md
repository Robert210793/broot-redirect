# US-11.005: Admin-Endpunkte vor unberechtigtem Zugriff schützen

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Betreiber
**möchte ich**, dass alle verwaltenden API-Endpunkte eine Admin-Session erfordern
**damit** Unbefugte weder Regeln noch Einstellungen oder Statistiken sehen oder ändern können

## Akzeptanzkriterien

- [x] Ohne Admin-Session antworten Regeln, globale Regeln und Statistiken mit 403 und einer JSON-Fehlermeldung
- [x] Das Ändern der Einstellungen erfordert eine Session, das Lesen nicht
- [x] Anmeldestatus, Abmelden und die Verwaltung blockierter IPs erfordern eine Session
- [x] Anmeldung, Health-Endpunkt und Pfade ausserhalb von `/api/` sind ohne Session erreichbar
- [ ] Auflösung, Erfassen und Feedback sind ohne Session erreichbar
- [x] Mit gültiger Session werden geschützte Anfragen durchgelassen

## Hinweise

- Der Schutz arbeitet mit einer Positivliste von Pfadpräfixen, nicht mit Attributen. Neue Admin-Endpunkte sind deshalb standardmässig öffentlich; ein neues API-Präfix muss zwingend in die Liste der geschützten Pfade aufgenommen werden.
- Belegende Tests: `AdminSessionMiddlewareTests`.
