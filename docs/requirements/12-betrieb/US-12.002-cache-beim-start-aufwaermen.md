# US-12.002: Daten beim Start in den Cache laden

> **Bestandsaufnahme:** Nachträglich aus dem Code abgeleitet (Stand 2026-10-24). Dokumentiert das Ist-Verhalten. `[x]` = durch automatisierte Tests belegt, `[ ]` = umgesetzt, aber ohne automatisierten Test. Keine fachliche Freigabe, keine Abnahme.

**Als** Benutzer mit einem alten Link
**möchte ich**, dass die Weiterleitung ohne Zugriff auf den Storage beantwortet wird
**damit** die Weiterleitung auch bei vielen Regeln schnell ist

## Akzeptanzkriterien

- [x] Beim Start werden Regeln, Einstellungen und globale Regeln in den Arbeitsspeicher geladen
- [x] Fehlt der Einstellungsdatensatz, wird er mit Standardwerten angelegt
- [ ] Beim Start werden fehlende Tabellen angelegt
- [x] Bis zum Abschluss gilt der Cache als «nicht aufgewärmt»; danach als aufgewärmt
- [x] Änderungen an Regeln aktualisieren die Indizes des Caches sofort, Massenlöschungen bauen sie nur einmal neu auf
- [x] Liegen noch keine Einstellungen im Cache, gelten die Standardwerte

## Hinweise

- Lesezugriffe enden im Cache; Table Storage wird nur beim Start und bei Schreibvorgängen berührt.
- Der Cache ist instanzlokal und wird nicht zwischen Instanzen abgeglichen. Die Anwendung ist deshalb mit genau einer Instanz zu betreiben; bei mehreren Instanzen liefern die übrigen bis zum Neustart veraltete Regeln aus.
- Belegende Tests: `CacheWarmupServiceTests`, `RuleCacheServiceTests`, `AppSettingsCacheServiceTests`, `GlobalRuleCacheServiceTests`.
